# PCLA Roadmap

> 非承诺性清单。条目按"用户价值 × 实现成本"排序，实施前必须单独出 spec。

## 重构方针（2026-10-22 更新）

上游代码是学生时代的产物，且上游仓库只随版本发布手动同步，因此 PCLA **不再要求与上游保持一致**：

- 允许激进重构：可以改变文件边界、删除死代码、重命名标识符，不再为"减少 diff"而保留原结构。
- 命名规范化优先于"尊重原风格"：新代码一律按 C#/.NET 惯例命名；被改动的旧代码顺手规范化，不要求与未改动部分统一。
- 行为兼容仍是安全网：在对应区域有测试覆盖之前，重构以现有行为为准；发现的上游缺陷记录到 `docs\TECHDEBT.md`，修不修另行决定。
- 已批准的 spec/plan 不追溯修改；新方针从下一个任务起生效。

## 提前项：全面 C# 化与 UI 框架更换

新方针下这两项从"远期"提到"可排期"，但顺序固定：

1. 先把行为锁进测试：下载层与启动参数层已完成，下一步覆盖实例模型、崩溃规则、配置读写。
2. 再抽业务核心到 C#：`McInstance`、设置、下载安装流程优先；VB 只留视图与事件绑定。
3. 最后换 UI 框架：核心层可测试后再选框架，避免把 WPF 控件逻辑直接翻译成另一套控件逻辑。

C# 化与 MCP 候选共用同一批核心层，谁先做都不返工。

## 候选项：UIA 自测能力（AutomationId）

**状态**：已实现。
**目标**：让 Agent 能自己跑 GUI 验收，不再每次请用户手点。

- 为导航、下载、实例列表等关键控件补稳定的 `AutomationId`（AID），不依赖可见文本定位。
- 用 `winapp ui` 驱动冒烟脚本：打开下载页、切换分类、确认版本行出现、截图与清理进程。
- 脚本首行必须走通用提示词里的同意闸门；无人值守运行只能由用户显式授权。
- 验收信号：同一脚本在 Release 产物上可重复跑通，失败时给出最后查询的控件树、stderr 与截图。

## 延后项：Settings 强类型化

**状态**：延后，等全面 C# 化之后用 Source Generator 处理。
**原因**：192 个键的访问器若用 PowerShell 脚本生成，缺少编译期检查，且需要手动同步；脚本解析 VB 源本身也是脆弱点。C# 工程切到 SDK 风格后，增量生成器可以读取注册表并直接产出强类型成员，编译期即可发现漂移。

## 候选项：PCLA MCP（stdio）

**状态**：构想，未排期。
**一句话**：把启动器已经具备的实例、日志、崩溃规则与社区资源检索能力，以只读 MCP 工具暴露给玩家自己的 Agent。

### 为什么值得做

- 目标用户是真实存在的交叉人群：用 Agent 的玩家，同时需要找 Mod/整合包/光影、排查模组冲突与性能问题。
- 这些能力 PCL 已经具备，缺的只是机器可调用的接口：实例模型在 `Plain Craft Launcher 2\Modules\Minecraft\ModMinecraft.vb`，崩溃规则在 `Plain Craft Launcher 2\Modules\Minecraft\ModCrash.vb`，资源检索在 `Plain Craft Launcher 2\Modules\Minecraft\ModDownload.vb`。
- Agent 直接读日志文件的成本高、准确率低：日志路径随启动模式变化、编码不统一、崩溃结论依赖约 60 条 `String.Contains` 规则。MCP 把这些判断收敛到启动器侧，Agent 只拿结构化结论。
- 对启动器本体零 UI 侵入：不需要新页面，不需要为非 Agent 用户增加任何可见入口。

### 明确不做

- 不做内置 Agent、对话界面或模型调用。
- 不做可插拔 Agent Tool 扩展；确实要做时另立设计，且必须按需加载，不占不用者的磁盘。
- MVP 不做写操作（安装、删除、改配置）。写操作要等只读工具跑顺、权限模型定稿后再议。

### MVP 工具集（只读）

| 工具 | 输入 | 输出 | 复用的现有能力 |
| --- | --- | --- | --- |
| `list_instances` | 无 | 实例名、MC 版本、加载器、Java、最后启动时间 | `McInstance` 列表 |
| `get_instance` | 实例名 | 完整版本/加载器/Mod 列表/内存设置 | `McInstance` + 版本 JSON |
| `read_log` | 实例名、行数或关键字 | 尾部日志或匹配片段 | `Log*` 文件 |
| `analyze_crash` | 实例名或日志路径 | 命中规则、置信度、涉及 Mod、建议 | `ModCrash` 规则表 |
| `search_resources` | 类型、关键词、MC 版本、加载器 | 名称、来源、下载量、兼容性 | `ModDownload` 的 CurseForge/Modrinth 检索 |
| `check_mod_conflicts` | 实例名 | 重复 Mod、缺失前置、版本不匹配 | 实例 Mod 元数据 |

`analyze_crash` 是价值最高的一项：它把"看日志"变成"拿结论"，也是 Agent 最容易做错的部分。

### 技术形态

- 传输：stdio，JSON-RPC 2.0。MCP 协议本身很薄，不需要引入官方 SDK 或 Node/Python 运行时。
- 宿主：优先做独立的小型 .NET 8 控制台程序，由用户在 Agent 配置里显式指向；不塞进 WPF 进程，避免 .NET Framework 4.8 与 MCP 生态的版本错位，也避免非用户多背一个常驻进程。
- 备选：现有 exe 增加 `--mcp` 隐藏开关，直接以控制台模式运行。省一个产物，但要处理 WPF 入口与无窗口生命周期。
- 配置：首次运行生成只读令牌与实例根目录白名单；所有路径参数都限制在白名单内。

### 风险

- 工具契约是长期负担：一旦公开，字段改名就是破坏性变更。MVP 阶段应标注 `experimental`，并接受一次大改。
- 日志与账号信息可能含隐私：默认只返回与崩溃相关的片段，不整段回传；路径中的用户名做脱敏。
- 与 UI 行为漂移：MCP 与启动器必须复用同一套规则与模型，不能各写一份。
- 受众规模有限：短期是差异化亮点，不是大众功能，排期优先级应低于稳定性与下载层重构。

### 验收信号

- 同一份崩溃日志，Agent 在接入 MCP 后给出的 Mod 定位与人工结论一致率显著高于直接读文件。
- 找资源从"打开浏览器、搜索、比对版本"缩短为一次工具调用加一次确认。
- 非 Agent 用户的安装包体积、启动路径、UI 无任何变化。

### 待定问题

- 独立进程还是 `--mcp` 开关。
- 是否需要把"安装"作为第二阶段写工具，以及确认交互放在启动器还是 Agent 侧。
- 多实例、便携模式、版本隔离下的根目录发现规则。
- 是否对外发布工具 schema，供第三方 Agent 客户端适配。

## 候选项：下载模块重设计（迁移完成后的优先事项）

**状态**：概念设计已完成，实施排期为**迁移完成后的优先事项**；实施前须基于当时引擎现状重新出详细设计。

**背景**：下载模块存在四个老问题——任务无法暂停/保存、代理检测不积极且不支持动态切换、退出程序任务全部消失、下载 UI 天然只适合单任务。下载引擎（NetFile/NetThread/NetManager）已 1:1 迁入 C# 并经实机冒烟验收，为重设计提供了带行为锁的演进基座。

**目标形态（四问题 → 四能力）**：

1. 任务级/全局级暂停 + `.tmp` 分块保留与 Range 续传；
2. 代理动态轮询探测，按用户三档偏好（`always | use_when_much_faster | never`）决定下载策略，运行中热切换；
3. 退出时任务清单与分块账本序列化，重启还原续传；
4. 全局任务面板（侧边栏入口，任务列表与页面解耦，后台可关页）。

**关键决策点（实施 spec 时定）**：引擎基座演进现有 C# 引擎（倾向，行为锁资产零浪费）vs 新写引擎；行为锁"解锁清单"（暂停能力是有意的行为变更）；代理热切换的 HttpClient 重建策略。

**验收锚**：暂停→恢复校验通过且耗时 ≤ 全量 70%；重启续传；代理切换 60 秒内生效；多任务后台继续；新增行为语料全绿——详见概念设计 §6。

## 待讨论：新功能方向（2026-10-27 头脑风暴，未排期）

> 以下条目仅记录方向与动机，均未立项；每条实施前必须单独出 spec 并走 brainstorming。

### 服务器部署与管理（Server Pack 一键开服）

- 动机：整合包普遍带 Server Pack，面板类产品（MCSManager、Pterodactyl）面向房管、门槛高；启动器侧"把整合包变成一台服务器"无人做顺。服务端安装三难点（版本清单、jar 下载、Java 管理）与客户端路径完全复用。
- L0 MVP：整合包 → 可玩服务器目录（服务端生成、headless installer、显式 EULA 确认后写 `eula.txt`、`server.properties` 端口/内存/motd）+ 启动/停止 + 日志查看（复用崩溃分析）+ 世界备份。纯本地、零服务端设施。
- L1：崩溃自动重启与通知、定时备份/重启、stdin/RCON 控制台、白名单管理。
- L2：联机可达集成（playit.gg agent、e4mc 模安装、frp 配置生成），"检测可达性 → 发链接给朋友"。
- 边界：多服务器面板化不做，偏离启动器定位。
- 安全红线：UPnP/端口映射必须显式同意；`eula.txt` 写入前必须有接受 UI。

### 实例还原点

- 装 Mod/改配置前自动硬链接快照，一键回滚；与服务器备份共用设施。成本极低、新手价值最高。

### 实例体检

- 重复 Mod 检测、日志加载耗时分析（哪个 Mod 拖慢启动）、内存/GC 建议。纯本地、复用日志解析。

### 存档管理

- 世界备份/回档 + 从 region 文件渲染 2D 预览图。演示效果好，渲染工作量大。

### 性能向导

- 按内存推荐 JVM 参数（Aikar/ZGC）、运行中 FPS/内存采样；与体检、还原点组成调优闭环。

### 优先级建议

服务器 L0 > 实例还原点 > 实例体检 > 存档预览 > 性能向导。云同步、皮肤站深绑、多语言不做（无差异化或成本失衡）。
